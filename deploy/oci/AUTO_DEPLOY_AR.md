# نشر OpenAgent التلقائي على Oracle

عند كل دفع إلى فرع `main`، تنفّذ GitHub Actions فحوص اللغة العربية وOAuth، ثم تبني الواجهة والخادم وصورتي التطبيق والساندبوكس بمعمارية ARM64 على خادم GitHub. إذا كان تفعيل النشر مضبوطًا، تُنقل الصور عبر SSH بمفتاح مخصص إلى خادم Oracle. لا تُنقل ملفات `.env` أو `config.json` أو قواعد البيانات إلى GitHub.

على الخادم، يحتفظ النشر بالمجلدات الدائمة لـ PostgreSQL وRedis والملفات وOllama. يأخذ نسخة احتياطية متناسقة قبل تشغيل ترحيلات قاعدة البيانات، ثم يعيد إنشاء الخدمات المتغيرة ويتحقق من صحة HTTP. عند فشل النشر يعيد تعريفات الخدمات والصور السابقة. **قد تتطلب ترحيلات قاعدة البيانات استرجاعًا يدويًا من النسخة الاحتياطية**؛ لا يوجد تراجع آلي عن البيانات. تحتفظ الآلية بصور الإصدار الحالي والسابق. لن تُنشر التغييرات التي تفشل في البناء أو الفحوص.

## التفعيل مرة واحدة بعد استرداد المثيل

1. يجب أن تصبح حالة المثيل `RUNNING` أولاً. حالة `STOPPING` العالقة لا يمكن إصلاحها بتعديل التطبيق أو GitHub Actions. لا تُنهِ المثيل ولا تستبدل قرص الإقلاع لاستعادة الاتصال.
2. ثبّت مفتاح SSH **جديدًا مخصصًا للنشر** في `/home/ubuntu/.ssh/authorized_keys` عبر وصول موثوق للخادم. احتفظ بالمفتاح الخاص خارج المستودع. افحص بصمة مفتاح المضيف من جلسة Oracle Console موثوقة؛ لا تقبل ناتج `ssh-keyscan` دون تحقق.
3. في GitHub، ضمن Settings → Secrets and variables → Actions، أضف الأسرار `OCI_HOST` (عنوان الخادم)، `OCI_SSH_PRIVATE_KEY` (المفتاح الخاص الكامل)، و`OCI_KNOWN_HOSTS` (سطر مفتاح المضيف الموثوق). اضبط المتغير `OCI_PUBLIC_URL` على رابط HTTPS العام للاختبار الخارجي، ثم اضبط `OCI_DEPLOY_ENABLED` إلى `true` **بعد** اختبار SSH يدويًا والتأكد من وجود `/home/ubuntu/open-agent/deploy/oci/.env` و`config.json` و`backup.sh` على الخادم.
4. شغّل workflow يدويًا مرة واحدة (`workflow_dispatch`) لنشر آخر نسخة، ثم راقب سجله ونتيجة الموقع. بعد ذلك ينشر كل دفع ناجح إلى `main` تلقائيًا.

إذا لم يوجد `OCI_DEPLOY_ENABLED=true`، يبني workflow الصور ويفحصها فقط ولا يتصل بالخادم. هذا مقصود حتى لا يدّعي نجاح نشر لا يمكن إتمامه أثناء توقف المثيل.

## أمن وتشغيل

- رمز GitHub الشخصي الذي كُشف في المحادثة يستخدم فقط للدفع الأولي ولا يُحفظ كسرّ للنشر. ألغِه وأنشئ رمزًا جديدًا بعد الدفع.
- لا تضف `.env` أو `config.json` أو المفاتيح أو ملفات النسخ الاحتياطي إلى المستودع. راجع الملفات المعدّة للدفع قبل كل نشر عام.
- فشل الاتصال أو نقص مساحة القرص أو فشل النسخ الاحتياطي أو فشل فحص الصحة يوقف النشر. لا تُحذف وحدات التخزين الدائمة تلقائيًا.
- ملف Nginx وشهادة TLS الحاليان يبقيان على الخادم. تحديث الواجهة والخلفية في صورة التطبيق يظهر عبر الرابط نفسه بعد اجتياز الصحة؛ تغيير النطاق أو الشهادة يحتاج إجراءً منفصلًا ومدروسًا.
- بناء الصور يتم خارج خادم Oracle لأن 1 OCPU و6 GB RAM ومساحة القرص المتبقية غير مناسبة لبناء Rust وواجهة المشروع عند كل دفع.
